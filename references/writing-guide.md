# 共同行文与素材规则

在 A、B 两种模式中使用；章节结构、深度和素材取舍服从本次用途及明确约束。

## 结构、语言与深度

用简体中文，准确、具体、直接地叙述。完整成品应独立成文，局部修订则与目标稿上下文衔接。通过少量职责明确的大章节展开知识与过程，合并重复和零散小节；不固定章节数量。

正文以连贯段落解释关系；并列比较、步骤、参数适合用列表或表格，不把整篇文章拆成碎片。综合整理技术学习资料时使用陈述式章节名；问答、试题和用户指定的问题式模板按对应要求处理。

陌生术语就近说明概念和当前作用，重要英文名称及缩写在首次出现时给出。必要时区分相近概念。新概念由实际问题自然引出，不给一句定义就接大段代码，也不用专业词汇代替解释。

关键过程应能看出谁执行、接收什么、怎样处理、产生什么，以及结果交给谁；说明原因和数据变化，必要时配简短数值例子。不要机械为每段生成这些小标题。流程图也要有完整的起点、处理、结果或反馈。

通过去重和改善组织控制篇幅，保留关键含义、条件、区别和必要解释。简单内容简写，关键过程充分展开。原理深度按任务决定，不为显得高级而增加抽象、技术方案或实现复杂度。

正文直接讲知识或工作内容，清理无助于阅读的聊天和编辑过程话术，例如“原文档如何描述”“与之前讨论一致”。正常出处及论文与代码对照需要的来源说明应保留。

不自动附加未要求的学习检查清单、概念速查、来源覆盖关系、修正记录或背景附录。内部核对和实施文档本身要求的验证内容分别处理。

## 按用途选择写法

下表用于新编稿或已获授权的结构重组；局部修改沿用目标稿确认过的结构。

| 用途 | 编写重点 |
|---|---|
| 技术学习 | 用途与必要概念、接入、常用功能、配置作用、前提、结果验证和问题处理；不自动深入底层源码或协议 |
| 论文详解 | 对应研究问题、方法、公式、图表、算法和结论，补足必要解释；与忠实翻译区分 |
| 代码讲解 | 先整体执行主线，再讲模块职责、调用关系和数据变化；短文件整体、长文件按功能模块；按要求采用注释或块下解析 |
| 实验报告 | 目标、条件、实际过程、结果；先主要指标与图表作用，再联合分析和总结成立范围 |
| 开发实施 | 可按“问题 → 思路及知识点 → 原业务流程 → 改进后流程 → 具体修改步骤 → 验证”展开 |
| 开发日志 | 沿用用户已有叙述格式，记录实际改动、必要代码与新知识；测试过程是否入稿按约定 |
| 接口文档 | 完整写调用约定、请求、响应、字段及限制；保持既定布局，嵌套对象和数组易读，依据已核实约定表述 |
| 研究现状、技术选型 | 当前问题、相关工作的方法成果指标与不足、方案依据；核对比较条件，保留作者和出处 |
| 组会汇报 | 整体主线、关键流程、实际成果和核心图表，减少无关基础铺垫 |
| 周报 | 按真实进展、指定日期和给定格式组织，不为了填满时段编造工作或成果 |
| 考试、面试资料 | 按知识层级由浅入深，保留重要概念、区别、公式、题目与必要解题过程，兼顾覆盖和复习负担 |

## 代码与图片

文档任务不自动授权修改业务代码。保留教学代码的主体，不为每段示例补齐完整工程、导包、启动代码和生产级容错。讲解说明类、方法或函数职责及关键操作的原因、数据变化和限制，说明放在对应位置；具体布局按用户要求。

标明占位方法、未启用分支、实现差异和未实现机制，不能只凭名称推断行为。源码原样保留或仅改排版的任务，保持执行逻辑；其他示例的明显错误只在允许范围内修正。

查看实际图片，保留与正文有关的原图，前有引入或后有解释，核对图号与“上图／下图”。按入口约定交付真实图片及相对引用，不用文字描述替代应保留的图片，不凭文件名猜内容。无法读取影响理解的重要图片时说明缺口并询问，不擅自删去。

## 公式、事实与出处

公式的包裹和目录默认值见入口。解释必要变量与物理含义，核对上下标、粗斜体、标量与矢量、编号和正文引用；核对实际显示。没有执行渲染时只报告语法或内容核对，不声称视觉显示已通过。

以实际资料为依据，区分论文原有事实、代码实现、运行结果、辅助例子和推断。可通过资料、代码或对应版本可靠文档确认的先核实，关注版本和时效。关键依据缺失时明确说明，必要时询问；若可以如实标注“未披露／未验证”并完成已明确的任务，不为这些缺口另设确认步骤。请求本身或影响结果的重要决定不明确时，仍按入口要求先询问并等待确认。不要捏造接口、配置、实验数据或实现状态。

结论范围与证据相符，计划、目标和他人成绩不当作已完成成果。不因简洁删掉影响理解的条件，也不反复插入无必要的保留意见打断主线。

保留有价值的视频、源码、示例工程、安装教程和配套学习链接。研究文献、图表、数据和报告观点保留必要出处，核查真实性；引用形式服从本次模板。
