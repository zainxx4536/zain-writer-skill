# A：修改完善已有文档

适用于纠错、补缺、精简、重排和续写。以目标稿和用户当前修改要求为起点。

## 读取与修改

- 阅读当前稿件及相关上下文，注意用户亲自改过的内容和现有未完成编辑。核对需要修改的事实，不把目标稿当作无需验证的权威。
- 识别这次要解决的问题，以及明确要求保留的章节、表述、代码、图表、公式、重点标记和链接。
- 局部修订沿用已确认的大结构和行文方式；只有明确要求重组时才合并、重排相关部分。结构取舍有歧义时按入口的澄清规则处理。
- 准确、清楚的好表述尽量保留，直接改正已确认的错误，补足缺失的前提、概念和过程。补充内容与上下文衔接，去除重复而保留关键含义和限制。
- 教学代码在允许范围内修正明显错误；要求源码原样保留或仅改排版时，保持执行逻辑，不自行改造实现。
- 图像存放和数学格式按入口约定处理；原始素材保留，成品引用同步更新。保护任务外的文件，不自动同步其他格式。
- 写回前确认没有覆盖用户在执行期间的新编辑。按本次授权决定原位更新或另存；覆盖范围不明确时先询问。

## 核对重点

对照修改要求检查问题是否解决，同时检查原有正确内容、保留部分和用户编辑是否仍在，是否引入矛盾、遗漏或格式损坏。

例如只要求补齐第二章的过程说明时，补充应落在第二章并与前后文衔接；第一、三章及指定保留的代码维持原样。另存为新文件不会改变这一边界。

成品正文直接呈现完善后的内容。修改说明在交付时简短交代，不自动附上修正记录、覆盖对照表或学习清单。
